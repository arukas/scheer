What it does

只做采集链路里真正重要的事。

Scheer 把平台差异留在扩展里，让你的后端只维护一套接收逻辑。凭据、历史和调试数据都留在本机。

01 / COLLECT

一键采集当前商品

自动判断当前页面能否采集，用户确认后才提取和提交，不做自动翻页或批量爬取。

02 / NORMALIZE

统一商品 Schema

不同平台的商品、规格、变体、价格和媒体，统一映射成结构稳定的 JSON。

03 / OWN

数据直达自有后端

目标地址、鉴权头和 Token 均由你配置。数据不经过 Scheer 的服务器，因为根本没有服务器。

04 / DEBUG

本地历史与脱敏日志

记录创建结果，按需开启 Debug 并导出 NDJSON 日志；敏感请求头会自动脱敏。

05 / FLEXIBLE

灵活的接口配置

支持域名加相对路径或完整 URL，也可调整鉴权 Header、前缀、自定义 Header 和超时。

06 / PRIVATE

隐私优先

扩展完全在 Chrome 中运行，凭据存于 chrome.storage.local，不上传账号密码。

API reference

后端只需实现两个接口。

默认路径是 /scheer/products 和 /scheer/me。两者都可以在扩展配置页改为完整 URL。

文档目录 鉴权 创建商品 字段结构 响应格式 测试连接 配置示例

鉴权

默认使用 Bearer Token。Header 名和前缀均可配置，自定义 Header 会覆盖同名默认值。生产环境请使用 HTTPS。 

Authorization: Bearer <secret>
Content-Type: application/json
默认请求超时为 30 秒。密钥仅保存在用户本机的 chrome.storage.local 中。

字段结构

价格以两位小数字符串传递，避免浮点误差。variants 和 images 始终为数组。

字段 类型 要求 说明
platform string 必填 平台代码
source_url string 必填 原商品页完整 URL
source_product_id string 可选 平台原始商品 ID
product.title string 必填 商品标题
product.options array 可选 规格维度、顺序和可选值
product.variants array 必填 变体列表；价格为 decimal 字符串
product.images array 必填 图片或视频列表
平台代码：shopify、newshop、shopbase、shopline、shoplazza、tiktok、amazon、wordpress、shadowshop。旧后端可将 newshop 映射为 wshop。

响应格式

HTTP 2xx 时返回 JSON。product_id 和 log_id 必须为非空字符串；扩展会把它们写入本地历史。 

{
  "product_id": "backend-product-id",
  "log_id": "import-log-id",
  "user": {
    "id": "user-id",
    "name": "Current User"
  },
  "message": "created"
}

HTTP 4xx / 5xx 时建议返回可直接展示给用户的错误信息：

{
  "message": "商品已存在"
}

测试连接

Options 页用此接口验证地址、鉴权和 JSON 响应是否正常。

GET https://api.example.com/scheer/me

返回任意合法 JSON 即可。扩展只检查 HTTP 2xx、非空响应体与合法 JSON。

{
  "id": "user-id",
  "name": "Current User"
}

扩展配置示例

配置页支持直接粘贴 JSON 或 Base64 编码的同等 JSON。

{
  "server": {
    "base": "https://api.example.com",
    "create_product_endpoint": "/scheer/products",
    "current_user_endpoint": "/scheer/me",
    "secret": "replace-with-your-token",
    "secret_header": "Authorization",
    "secret_prefix": "Bearer",
    "timeout_ms": 30000
  }
}
